# 任务包工作流

## 输入检查

- 目标、受众、最终交付物与时间是否明确。
- 已有资料、可用资源和不可触碰边界是否明确。
- 缺失但会改变执行方向的信息列为待确认，不自行补写。

## HTML 任务包要求

最终交付为一个独立 HTML 文件，不依赖网络、图片或第三方前端资源。使用语义化标签和内嵌 CSS；至少包含以下内容区块：

- 页面标题与任务状态。
- 任务说明：目标、使用者/受众、最终交付。
- 输入与待确认：已知输入与待确认项分开呈现；待确认项使用醒目但不过度警示的状态样式。
- 执行计划：每一步均展示序号、动作、产出和通过标准。
- 交付清单：使用清晰的完成/未完成状态。
- 验收标准、风险与下一步。

安全要求：

- 所有来自附件、转写、聊天或用户材料的动态文本必须按所处 HTML 上下文编码，至少处理 `&`、`<`、`>`、双引号和单引号；不得把材料原文作为 HTML、CSS 或属性值直接拼接。
- 禁止 `script`、`iframe`、`object`、`embed`、`form`、`base`、`link`、SVG/MathML 活动内容、meta refresh、`on*` 事件属性、`javascript:` URL、CSS `@import` 和任何网络资源。
- `<head>` 中必须加入：`<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'">`。
- 生成后、打开前，运行 Plugin 根目录的 `scripts/check_html_safety.py` 检查成品；检查失败时不得交付或打开，先修正后重跑。

视觉要求：

- 使用清晰的标题层级、充足留白、易读的正文字号和卡片分组；避免密集的纯文本列表。
- 以电脑端阅读为准，内容宽度适中，正文与表格清晰易读。
- 采用中性、专业的配色；不使用夸张渐变、闪烁或与内容无关的装饰。
- 在页脚明确“本地任务包，不代表已对外发送、发布或交付”。

## 结构草案

```text
[任务名称]  |  本地任务包  |  [完成状态]
任务概览：目标 / 受众 / 最终交付
输入与待确认：已知输入 / 待确认
执行计划：步骤 / 动作 / 产出 / 通过标准
交付清单
验收标准
风险与下一步
页脚：本地任务包边界说明
```

生成后先运行安全检查，再实际打开或读取 HTML；核对信息完整、页面有标题、无内容溢出，并确认所有未知事实仍为“待确认”。

## 课堂示例

输入：一段“下周要给客户讲清楚服务包”的语音转写。

最小成果：明确汇报对象、待补资料、PPT 初稿步骤与逐项验收标准；不代替用户确认报价、日期或客户信息。
